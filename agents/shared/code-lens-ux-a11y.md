## UX and accessibility checklist

First decide whether the change touches anything a user sees or operates. If it does not, say so; there is nothing to review in this lens.

Look for missing loading, empty and error states, errors swallowed without feedback to the user, keyboard access and focus order, missing labels or accessible names, color contrast below WCAG AA (4.5:1 for text), click targets too small to hit, layouts that break or overflow at narrow widths, and user-facing copy that is unclear or inconsistent with the rest of the product.

Follow the project's existing design system, tokens and components; never ask for a new visual style, color or dependency. Separate what the source proves from what only a rendered view could show.
